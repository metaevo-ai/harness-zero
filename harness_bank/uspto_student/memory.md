# Harness memory (uspto)

Accumulated checklist clauses distilled from harness evolution on USPTO
retrosynthesis tasks. Generic English phrasing, no per-task provenance.
Workers receive tailored excerpts via manifest `memory`.

## Output & answer discipline

- [ ] The grader is an exact string SET match (order-free, case-normalized, "."-separated) with NO chemical canonicalization — ship every reactant in RDKit-canonical form; a chemically-correct molecule written in a non-canonical string scores 0.
- [ ] Strip atom-mapping numbers before writing the answer; they break the string match.
- [ ] Write the answer file as ONE line — reactant SMILES joined by "." with no spaces and no prose — then read it back before finishing.
- [ ] Never finish with the answer file missing or empty; that scores 0 regardless of the chemistry.
- [ ] Write a best-guess answer file as your FIRST action, then refine it in place — a run that dies mid-analysis still scores whatever is on disk, while an unsubmitted perfect analysis scores 0.
- [ ] Validation must come AFTER the answer file's last write — a check run on an earlier draft is stale evidence; re-run the mechanical battery whenever the file was rewritten since.
- [ ] Product given as a salt (a bare `[Na+]`/`[K+]`/halide among the dot-separated components) → keep the ionic group ionic in the reactants and ship the counterion as its own dot-separated reactant component; upgrading a salt to the free acid or an acyl derivative scores 0.
- [ ] Amine reactants have two first-class spellings — free base and protonated `[NH3+]` salt; when the reaction context implies an amine salt (amine protections, products recorded as HCl salts), enumerate both explicitly instead of defaulting to the neutral form.
- [ ] Copy tool-canonicalized SMILES into the answer file character-for-character, and never retype, reorder, or "simplify" a fragment by hand afterwards — an alternate valid spelling of the correct molecule is a string mismatch, so hand-reverting a canonical string after validation throws the score away; the canonicalizing final gate must be the LAST action before finishing.
- [ ] The answer file has exactly ONE writer: the worker that solved the task. Any audit or double-check agent must be read-only and report-only — a second agent with write access can overwrite a verified-correct answer with a hand-derived wrong variant, and format-level re-verification cannot catch a chemistry-level overwrite; once the solving worker's final verification passes, the file is sealed and nobody writes it again.

## Verification & chemistry-specific checks

- [ ] Never eyeball-parse or hand-transcribe a SMILES — validate and canonicalize every structure with RDKit; fused rings and ring-substitution positions drift when copied by hand.
- [ ] Every candidate reactant set must pass mechanically: all fragments parse, the summed heavy atoms account for EVERY product heavy atom, and each fragment's MCS overlap with the product is near-complete — coverage well below 1.0 means skeleton drift (wrong ring, wrong substituent position), not a creative disconnection.
- [ ] Forward-plausibility: every proposed disconnection must map to a real forward reaction — the electrophile bears a leaving group at the reaction center; a cross-coupling substrate without a halide/triflate handle cannot react.
- [ ] Elements found in reactants but not the product must be explainable as leaving groups/reagents/byproducts (halides, P, S, B, metals, water); any other surplus or deficit means a dropped or invented fragment.
- [ ] Co-reactant convention: the recorded reactant set contains every species that contributes heavy atoms to the product — including small donors (ammonia equivalents, protecting reagents, acyl donors) — and usually excludes species that contribute none (oxidants, reductants, acids/bases, solvents). Audit the final set against this convention.
- [ ] Keep stereo tags consistent with the product's own record: preserve tags on untouched stereocenters exactly and stay minimal near the reacted center — reference reactant strings often omit stereo there; a surplus or missing `@` is a string mismatch and scores 0.
- [ ] Alkene E/Z follows the opposite convention from stereocenters: a restored or newly formed acyclic C=C is usually stereo-DEFINED in the reference record — write the `/`/`\\` geometry markers on that double bond (default E/trans for conjugated alkenes unless the scaffold forces Z) instead of shipping it unspecified; an unspecified double bond mismatches a geometry-defined reference exactly like a wrong tautomer.
- [ ] Candidate scoring is not submission validation: per-candidate checks rank candidate SETS, but the answer file must still pass the final contract battery after its last write — skipping the file-level gate ships uncanonicalized or contract-violating strings.
- [ ] For protection/deprotection steps, name the protecting group explicitly and check the partner count: a protection records BOTH the free substrate and the protecting reagent (in its common commercial form); a deprotection usually records only the substrate.
- [ ] For protection steps, build the free substrate by DELETING the protecting group from the product and changing nothing else, and anchor the choice with atom arithmetic: its heavy-atom count must equal the product's minus the protecting group's (a Boc group is 7 heavy atoms, C5O2). A candidate whose count violates the arithmetic is a redrawn skeleton (extra carbonyl, wrong ring size), not a stripped precursor — discard it even when its canonical string passes every gate.
- [ ] For oxidation/reduction steps, the answer is usually the single organic substrate exactly one oxidation level away — adding a redox agent that contributes no atoms to the product (H2, hydrides, acids/bases) turns a solved task into a zero. Exception: atom-transfer oxidants whose oxygen ends up IN the product are recorded — peracid epoxidation of an alkene and sulfide → sulfoxide/sulfone oxidation list the peracid (mCPBA) as its own reactant component.
- [ ] A verification step must discriminate between your enumerated candidates — re-deriving your own candidate's formula or re-reading the answer file proves consistency, not correctness; a wrong candidate is usually self-consistent too.
- [ ] A missing verification library is an installation step, never permission to skip validation: pypi is reachable from the sandbox and `pip install rdkit` takes seconds — an ImportError followed by an unverified answer is a process failure, not bad luck.
- [ ] Balance TOTAL FORMAL CHARGE, not only elements: summed over the reactants it must equal the product's — a mismatch is a dropped counterion or a wrong protonation/salt state even when the heavy-atom count looks fine.
- [ ] A recorded single step changes ONE site: confirm mechanically (MCS changed-site count) that the chosen precursor differs from the product at one bond-contiguous site — a precursor differing at 2+ disconnected sites means over-transformation; sulfones, halides, and pre-installed protecting groups keep the product's exact state.
- [ ] For redox steps, enumerate the full oxidation ladder at the chosen site (e.g. alcohol / aldehyde / carboxylic acid) and fix the rung with the formula delta — ladder rungs differ by H2 or by O; a near-miss rung scores zero like a wrong molecule.
- [ ] The rung of an oxidation ladder cannot be fixed by mechanical checks alone — every rung passes skeleton/site/formula validation; choose by recorded-frequency prior (deep reductions of a carboxylic acid or ester straight to the alcohol are recorded about as often as the nearest rung) and never default to the aldehyde/ketone merely because it is one step away.
- [ ] A bare element or ion (a lone halogen atom, `Na`, `Cl`) is NEVER a recorded reactant — every element the product gained must be delivered by a named molecule (the standard reagent for that transformation); if you cannot point at which product atoms a co-reactant supplies, drop it.
- [ ] A transform-library candidate carrying its recorded co-reactant must not be dropped over an "extra elements in reactants" flag on that co-reactant's departing atoms — a donor reagent's leaving fragment never appears in the product, so that flag is expected noise for a reagent-bearing candidate, not a kill signal; substituting a hand-picked reagent for the library's recorded one turns a solved task into a zero.
- [ ] A restored unsaturation adjacent to a carbonyl records as the CONJUGATED isomer (C=O directly on the C=C), not the non-conjugated position isomer one carbon away — position isomers share the formula, so no mechanical check can separate them; the site choice is explicit chemistry judgment (conjugation thermodynamics + dataset frequency), never something the battery will catch.

## Process & decomposition

- [ ] Generate 2-4 candidate disconnection sets before committing: enumerate the named reaction type's classic precursor patterns x every plausible bond/functional group in the product; never ship the first plausible idea.
- [ ] Use the reaction-type label as a candidate filter and ranking prior, not as the answer itself (e.g. under "Reductions", enumerate N-oxide, protected OH, nitro, carbonyl, alkene precursors — then rank).
- [ ] Score candidates mechanically first, then by dataset precedent (common reagents, standard protecting groups, standard handles); keep the scoring on disk and commit to ONE set — hedging is impossible.
- [ ] For FGI-type steps, inventory EVERY functional group of the product and give each 1-2 precursor proposals before choosing the interconversion locus — the recorded step often changes a plain group, not the eye-catching one.
- [ ] For oxidation steps, inventory EVERY oxidizable center (secondary alcohol, sulfide, aldehyde, amine, alkene, benzylic carbon) and give each a de-oxidized candidate before choosing — the recorded oxidation is often not the most salient oxidized group.
- [ ] For deprotection steps, enumerate the standard protecting-group identities for the freed site (ester: methyl/ethyl/benzyl/tert-butyl; amine: Boc/Cbz/Fmoc; silyl ethers) and rank by which deprotection is commonest in the dataset — never ship the first identity that comes to mind.
- [ ] Never infer a protecting group's identity from an unrelated group elsewhere in the molecule (an existing tert-butyl substituent is no evidence the masked acid was a tert-butyl ester); identity choices come from the enumerated candidate list and dataset prior only.
- [ ] When candidates differ only in WHICH protecting group or handle identity they assume, rank by the smallest atom delta vs the product first — observed loss: an arm enumerated the correct minimal-edit precursor and a bulkier familiar-group precursor, computed both formulas, and still shipped the bulky one on a frequency prior; dataset frequency breaks ties, it never overrules the minimal edit.
- [ ] For heterocycle-formation steps, write the ring-atom provenance table (which partner supplies each ring atom and substituent) BEFORE writing any partner SMILES — named cyclizations have fixed provenance, and assigning a substituent to the wrong partner is the classic silent loss.
- [ ] For heteroatom alkylation/arylation steps, the recorded set is TWO components — the dealkylated substrate plus the alkylating agent (e.g. an alkyl halide) — and the only bond disconnected is the heteroatom-substituent bond, never a ring bond; check the freed heteroatom's protonation state (`[nH]` vs bare `n`).
- [ ] For alkylation steps, enumerate the alkylating agent across halide identities (Cl / Br / I) as separate candidate sets and score each before choosing; N- and O-methylation records most often use methyl iodide — rank it first among methylation candidates.
- [ ] When a heteroatom alkylation/arylation product carries several heteroatom–carbon bonds, every candidate C–O/C–N disconnection passes atom balance equally — rank sites by the acidity/nucleophilicity of the freed heteroatom: a hydroxy-heteroarene, enol, or phenol OH outranks any aliphatic alcohol as the recorded alkylation site, and the electrophile partner is correspondingly the benzylic or primary alkyl halide fragment; never break a tie by list position.
- [ ] Prefer the minimal heavy-atom edit consistent with the named class: the recorded precursor usually differs by one small group, not by a dramatic rearrangement.
- [ ] For functional-group-addition steps (a new group on a C-H, e.g. benzylic/allylic halogenation), the recorded set is TWO components — the de-functionalized substrate plus the addition reagent (e.g. N-bromosuccinimide for bromination) — and pre-existing amide/ester bonds in the product are NOT the disconnection site.
- [ ] For heterocycle-formation steps, the newly formed ring appears in NO reactant — submitting the intact ring system (or the whole product with a cosmetic edit) as a reactant means the reaction-type hint was ignored; identify the ring class (size, heteroatom count, unsaturation) from rdkit's ring inventory before choosing the named cyclization to reverse.
- [ ] Three or more reactant components is an over-disconnection red flag: re-check whether two fragments are actually one recorded reactant (e.g. a β-ketoester rather than an acid chloride plus a separate piece) and whether a group you disconnected was installed in an earlier step (carbamates under an Acylation context).
- [ ] Enumerate candidates mechanically BEFORE reasoning by hand: run the transform-library enumeration on the product with the stated reaction type, then choose among its candidates — observed losses trace to committing to the first in-head disconnection.
- [ ] An epoxide (three-membered O heterocycle) records overwhelmingly as alkene + peracid epoxidation — do not disconnect pendant ethers or invent diol/dihalide precursors for it.
- [ ] A free primary aliphatic amine at a stereocenter, alongside OTHER protected amines, commonly records as the azide (azide reduction retains configuration) — under an FGI/Reduction label prefer the azide precursor over removing a protecting group.
- [ ] The stated reaction type is a HARD filter that outranks every motif prior: a candidate whose transform belongs to a different class is disqualified no matter how salient its motif — a C–C coupling (Sonogashira/Suzuki/Heck) is never an FGI, Protection, Reduction, or heteroatom-alkylation step, and a plain deprotection belongs to the Deprotection class, not FGI.
- [ ] An aryl–alkyne motif (Ar–C≡C–R) records predominantly as Sonogashira coupling — aryl halide + terminal alkyne — even when R is a tertiary carbinol that also admits a ketone + acetylide reading; check the aryl-halide split first, but ONLY when the stated reaction type is a C–C-coupling class or no type is stated.
- [ ] Candidate sets that differ only in fragment placement of the SAME disconnection are one hypothesis, not an enumeration — width means distinct named transforms; if every candidate fails the "maps to a real forward reaction" test, the family is wrong, not the spelling.
- [ ] The halide identity on a (hetero)aryl electrophile is a ranked choice, never a guess: enumerate Cl / Br / I variants as separate candidate sets and rank by the named reaction family (chloride is the commonest recorded handle for SNAr amination of heteroarenes; cross-coupling records split between chloride and bromide at the same order of frequency with iodide essentially absent — never default to bromide out of cross-coupling habit).
- [ ] Complementary Suzuki handle assignments (which partner bears the halide vs the boronic acid) all pass mechanical checks equally — rank them by chemistry, never by emission order: when one partner is a 2-amino-azaheterocycle (aminopyridine/aminopyrimidine class), the heterocycle bears the halide and the carbocyclic partner bears the boronic acid, because 2-aminoheteroaryl boronic acids protodeboronate and are rarely recorded as reactants.
- [ ] For acylation steps, a FREE beta-ketoacid as the acyl-donor candidate (RCO-CH2-COOH) is a red flag: beta-ketoacids decarboxylate readily and are rarely the recorded reagent — when an ester form of the same beta-keto donor is enumerated, ship the ester. Ordinary stable carboxylic acids are unaffected: the free acid remains their standard recorded form.
